# Демонстрация работы ноды patrol (ПР03)

## 1. Роли механизмов ROS 2 и Python

### Роль `rclpy.init(args=args)`:
Инициализирует глобальный контекст клиентской библиотеки ROS 2 (RCL) для Python. При этом создается структура данных процесса, парсятся стандартные аргументы командной строки ROS (например, `--ros-args`, переназначения `-r`, параметры `-p`), настраиваются сигналы операционной системы и инициализируется внутренний слой связи (DDS middleware). Без вызова `rclpy.init()` невозможно создавать ноды, топики или таймеры.

### Роль `rclpy.spin(node)`:
Запускает блокирующий цикл обработки событий (Event Loop) исполнителя (Executor) по умолчанию (SingleThreadedExecutor). В этом цикле поток ожидает событий из очереди ожидания DDS (поступление сообщений в подписки, срабатывание таймеров, ответы на вызовы сервисов) и вызывает соответствующие функции обратного вызова (**callbacks**). Метод `spin` держит ноду в живом состоянии, пока не будет запрошено завершение работы (например, через `rclpy.shutdown()`).

### Роль Callbacks (функций обратного вызова):
ROS 2 построен на событийной архитектуре (event-driven). Разработчик не опрашивает входящие сокеты в `while True`, а регистрирует callbacks:
- **Callback подписки (`pose_callback`)**: вызывается исполнителем всякий раз, когда в топик `/turtle1/pose` приходит новое сообщение с позой. Функция получает десериализованный объект `Pose` и сохраняет его в атрибут `self.latest_pose`.
- **Callback таймера (`timer_callback`)**: вызывается с заданной частотой (каждые 0.1 с / 10 Гц). Внутри вызывается чистая функция вычисления скорости `compute_cmd_vel` и публикуется сообщение `Twist`.

### Роль `Ctrl+C` и корректной остановки:
При нажатии `Ctrl+C` терминал посылает сигнал `SIGINT` процессу Python. Блок `try ... except KeyboardInterrupt` перехватывает сигнал, позволяя выйти из `rclpy.spin()`. В блоке `finally` вызываются:
- `node.destroy_node()` — уничтожаются все созданные подписки, издатели и таймеры, а также освобождаются ресурсы сущностей DDS.
- `rclpy.shutdown()` — финализируется контекст RCL и завершаются внутренние потоки.

## 2. Эксперимент: дефект имени топика (Сломать)

### Запуск ноды без переназначения:
```bash
ros2 run patrol patrol
```
Вывод в терминале:
```text
[INFO] [patrol]: Нода patrol запущена, ожидание позы...
```

### Наблюдение за turtlesim:
Черепаха в окне **остается неподвижной**.

### Диагностика графа и топиков:
```bash
ros2 topic info cmd_vel --verbose
```
Вывод:
```text
Type: geometry_msgs/msg/Twist
Publisher count: 1
Node name: patrol
Node namespace: /
Topic type: geometry_msgs/msg/Twist
Endpoint type: PUBLISHER
Subscription count: 0
```

```bash
ros2 topic info /turtle1/cmd_vel --verbose
```
Вывод:
```text
Type: geometry_msgs/msg/Twist
Publisher count: 0
Subscription count: 1
Node name: turtlesim
Node namespace: /
Topic type: geometry_msgs/msg/Twist
Endpoint type: SUBSCRIPTION
```

### Причина сбоя:
Издатель в ноде `patrol` был объявлен с **относительным** именем топика `'cmd_vel'`. Так как пространство имен ноды по умолчанию `/`, полное имя топика стало `/cmd_vel`. Однако нода `turtlesim` слушает топик `/turtle1/cmd_vel`. Поскольку имена топиков не совпадают, у `/cmd_vel` 0 подписчиков, и команды управления не доходят до черепахи.

## 3. Эксперимент: исправление через Remapping (Доказать)

### Запуск ноды с флагом переназначения:
```bash
ros2 run patrol patrol --ros-args -r cmd_vel:=/turtle1/cmd_vel
```

### Наблюдение за turtlesim:
Черепаха непрерывно движется вперед и поворачивается по дуге окружности (`linear.x = 0.5`, `angular.z = 0.3`).

### Проверка сопряжения топика:
```bash
ros2 topic info /turtle1/cmd_vel --verbose
```
Вывод:
```text
Type: geometry_msgs/msg/Twist
Publisher count: 1
Subscription count: 1
```

### Измерение реальной частоты публикации за 10 секунд:
```bash
ros2 topic hz /turtle1/cmd_vel --window 100
```
Вывод:
```text
average rate: 10.002
	min: 0.098s max: 0.102s std dev: 0.00114s window: 100
```
*Результат*: средняя частота составляет ~10.0 Гц, что в точности соответствует заданному периоду таймера 0.1 с.

### Остановка ноды и поведение turtlesim:
При остановке ноды `patrol` через `Ctrl+C` публикация команд прекращается. Нода `turtlesim` не останавливается мгновенно в ту же миллисекунду: у симулятора есть внутренний таймаут (по умолчанию 0.5–1.0 с), после которого при отсутствии новых входящих команд черепаха плавно сбрасывает скорость до нуля. Исчезновение процесса управления не является командой торможения.
